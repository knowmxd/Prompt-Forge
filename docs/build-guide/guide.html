Our journey so far

Chapter 1What is Prompt Forge?

A workshop for building really good instructions for AI image generators.

When you ask an AI to make a picture, the words you type are called a prompt. A lazy prompt (“a knight on a cliff”) gets a lazy picture. A great prompt describes the person, the clothes, the pose, the camera, the lighting, the mood, and even what to avoid. That’s a lot to keep track of, and most people forget half of it.

Think of it like this A prompt is a recipe. Prompt Forge is the recipe card with labeled boxes: Ingredients, Oven temperature, Cooking time. You can’t forget the oven temperature when there’s an empty box staring at you.

What it does, in four verbs

1
Paste any messy prompt
2
It sorts the words into slots
3
You edit or click in ready-made looks

…and then 4, you copy the finished prompt out as clean JSON (a tidy, labeled text format) and paste it into your image tool.

Jargon check · JSON JSON (say “JAY-son”) is a way of writing information as "label": "value" pairs, grouped inside curly braces. Computers love it because it’s predictable; humans can read it too. Example: "lens": "85mm".

Who it’s for

Artists and photographers who make images with AI and want repeatable, high-quality results: character artists (knights, elves, rangers), portrait and fashion shooters, and anyone who wants a library of proven poses and camera setups to pick from instead of reinventing them every time.

Chapter 2The big picture

Everything the app does fits into four steps.

The whole app in one picture.

Step by step

  1. Paste. You drop any prompt into the Source box on the left. Paragraph, comma-separated tags, or existing JSON all work.
  2. Parse. The app reads it and files each phrase in the right slot (“85mm lens” goes under Optics, “long silver hair” under Hair). Parse just means “read and organize.”
  3. Edit. Every slot is a text box in the middle of the screen. Fill empty ones, or click a ready-made Look (a pose, camera angle, light, or setting) from the right-hand shelf.
  4. Copy. A live JSON preview at the bottom updates as you type. One button copies it.
Jargon check · Frontend vs. backend The frontend is everything you see and click in the browser. The backend is code that runs on a server somewhere else, usually to save data. Prompt Forge is mostly frontend; the backend only wakes up when you sign in to save to the cloud.

No AI inside the parser

An important detail: the parser doesn’t call any AI service. It uses rules (keyword lists and pattern matching) so it’s instant, free, works offline, and gives the same answer every time. The AI you’ll eventually use is the image generator that receives your finished prompt.

Chapter 4The Prompt Blueprint

Fifteen slots, in four groups. Every prompt gets sorted into the same shape.

The 15 “clusters” you see in the left-hand menu of the workbench.

Under the hood each slot is a field inside one big nested JSON object, defined in model.ts as a type called PromptDoc. Here’s a trimmed view of that shape:

"aesthetic_dna": {
  "medium_format": "oil painting",
  "optics": { "lens_type_and_focal_length": "85mm", "aperture_and_dof": "f/1.4" },
  "lighting_architecture": { "key_source": {…}, "accent_and_practicals": {…} },
  "color_science": { "dominant_palette": ["#8A1C1C"] }
},
"scene_composition": { "framing_doctrine": {…}, "environmental_staging": {…} },
"subjects": [ { "subject_id", "casting_and_physique", "kinetic_posture", "wardrobe_architecture"… } ],
"creative_thesis": {…},
"anti_cliche_exclusions": ["no text", "no watermark"]
Think of it like this It’s a filing cabinet with four drawers, and each drawer has folders. “Subjects” is a list, so you can have several characters in one scene, each with their own pose and wardrobe.

Why a strict shape matters

  • Nothing gets forgotten. Empty slots are visible. The app shows “16 filled” style counters.
  • Looks can write to exact spots. A pose card knows to write only into kinetic_posture; an angle card writes into framing and optics. They never overwrite each other.
  • Old data still works. A coerceDoc() function repairs older or malformed saves into the current shape instead of crashing.

Chapter 5The parser

The sorting machine that turns one messy sentence into 15 tidy slots.

Here’s the sample prompt that ships in the app. We ran the real parser on it. The result below is its actual output, not a mock-up.

Orange = the person · Blue = the scene · Teal = the look · Pink = things to avoid.

How it decides

  1. Detect the format. Is it JSON? Labeled lines (Hair: silver)? Plain sentences? The parser reports which mode it found (json, labeled, freeform) and says things like “Sorted this into 10 sections.”
  2. Split into phrases at commas, “and,” “with,” and similar joiners.
  3. Match keywords. Lists of words route phrases: “lens, mm, f/” → Optics; “hair, braid, beard” → Hair; “armor, cloak, boots” → Wardrobe; “no …, without …” → Exclusions.
  4. Peel off special things. Hex color codes like #8A1C1C go to the palette; Midjourney-style flags and aspect ratios get stripped out of the way.
  5. File it into the Blueprint using assemble.ts.
Jargon check · Regex A regular expression (“regex”) is a tiny pattern language for matching text. For example, /\b(hair|braid|beard)/i means “find any of these words, ignoring capital letters.” The parser is full of them.
Honest limits Rules can’t understand meaning the way an AI can. Phrases that don’t contain a known keyword may land in a general slot, so a quick glance and tweak after parsing is part of the workflow. In the sample above, “weathered” was also copied to Wear & patina and “leather” to Textiles. That’s the keyword rules doing their best.

Chapter 7Where your stuff is saved

Three places, and only one of them needs an account.

Everything works offline. Signing in adds a copy in the cloud.

Why three places?

  • localStorage is a small notepad built into every browser (about 5 MB). It’s perfect for text but too small for photos.
  • IndexedDB is a bigger browser database. Photos go there as blobs (raw file data).
  • The cloud (PostgreSQL) is a real database on a server. A server function in cloud.ts checks who you are with authMiddleware and then reads or writes only your rows. The two tables are created by the file migrations/0002_library.sql.
Jargon check · Migration & middleware A migration is a small script that creates or changes database tables, like a construction blueprint for the filing cabinet. Middleware is a checkpoint that runs before your code, here it’s the bouncer that asks “who are you?” before letting a request touch saved data.

Safety nets

  • Every read goes through a “coerce” function that cleans unexpected data, so a corrupted save can’t break the app.
  • Storage keys are versioned (prompt-forge:library:v2) so future changes can migrate old saves safely.
  • Old field names (like clothing or camera) are translated to the new cluster names automatically.

Chapter 8The Pose Library

Out with the stick figures. In with 97 studio-quality poses.

The problem

The first version drew poses as tiny wobbly stick figures. They were hard to read and looked cheap, and a pose reference is only useful if you can actually see the pose. So we removed them completely and started over with a different goal: a big, well-organized library that feels like a photo-studio reference book.

NEW: neutral matte mannequin. Shape and weight are clear.
OLD: stick figure (illustration). Removed.

How we planned it

Before building, we asked a round of questions and you answered them. The decisions that shaped everything:

  • Use existing-style imagery, not hand-drawn art. Easiest for us to produce and the quality is much higher.
  • Organize for real use. Not just standing/sitting, but by subject: knights & warriors, fashion & photo shoots, fine-art paintings, cinematic scenes, couples, and so on.
  • Quality over quantity, with hundreds as the long-term goal. We shipped 97 strong ones first.
  • Subject-specific poses are a later step. (A knight’s pose won’t suit a portrait shoot.) For now, categories carry that meaning.

How the images were made

  1. Generate a contact sheet. One AI image shows a 3×3 grid of nine poses of the same neutral grey mannequin on a white background.
  2. Slice it. A script cuts each sheet into nine separate JPEGs in public/poses/.
  3. Describe each pose in words. Every card gets a written posture sentence, because that sentence is what goes into the prompt.
  4. Register it in the database file with an ID, category, stance and search tags.
One generated contact sheet (Knights & Warriors) before slicing into nine cards.

Chapter 9Camera & Angles

27 options, all shown with the same plant, so the angle is the only thing that changes.

Why a plant? If every example used a different subject, you’d be comparing apples to oranges. A monstera in a white pot on a plain pedestal is the same in every picture, so when the view changes you instantly see what the camera did: the leaves stretch, the pot shrinks, the background melts away. It’s a science-fair control experiment for photography.
Positions are where the camera sits. The badge numbers on the cards (like “+60° WORM”) describe how steeply it tilts.

Lenses & depth of field
Photo words, translated Focal length (mm): how “zoomed” the lens is. Small = wide view, big = zoomed in. Aperture (f/number): how wide the lens opens; a small f-number (f/1.4) lets in lots of light and blurs the background. Depth of field (DoF): how much of the picture is in focus. Bokeh: the soft, creamy blur. Dutch angle: tilting the camera so the horizon slants, for tension. Nadir: straight down.

Chapter 10The “Looks” engine

One tiny function that makes every card in the app work.

Poses, camera angles, lights and settings look different but behave the same way: click, then write some text into specific fields. So we gave them one shared shape, called a Look, and one function, applyLook(), that knows where each kind writes.

Four kinds of card, one function.

What the shelf shows

  • Filters: All · Camera & Angles · Knights · Photoshoot · Fine Art · Cinematic · Couples & Duos · Action · Sitting · Floor · All Poses · Light · Setting.
  • About 160 looks in total: 117 poses, 33 angles, 5 lights and 3 settings. The poses include the 97 new ones plus older entries kept so existing prompts still work.
  • Applied marker: lookIsApplied() compares your current prompt with each card, so the card currently in use shows a check mark.
  • Content gating: a few legacy poses are flagged adult. They’re excluded from every normal shelf and appear only under their own filter. A test guards that they never leak into the modeling shelf.

Next stepsRough edges & roadmap

Known rough edges (worth fixing)

IssueDetail
Numbers burned into pose photosThe big digits (“5”, “2”, “7”) in the corners of many pose cards are leftovers from the contact-sheet grids. Re-cropping a little tighter, or regenerating without numbers, fixes it.
Captions burned into camera photosEach plant card has its own text (“Eye-Level Direct Frontal”) baked into the picture, which duplicates the title underneath. A few cards also show a small corner artifact from the grid.
Clipped ID badges in the sidebarIn the narrow right shelf, IDs like ANG-EYE… are cut off. Shortening or hiding the ID there is a quick CSS tweak.
Leftover stick-figure dataThe old drawing file figure.ts is still in the code. It no longer appears as cards, and can be deleted in a cleanup pass.
Small pose collectionsSitting (5), Casual (4), Fantasy (3), Floor (3) are thin compared with the 18-pose collections.

Roadmap

The same treatment for clothing: reference sheets for knight plate armor, techwear, editorial fashion, historical regalia and fantasy robes. Each card would write into the Wardrobe slot (layers, textiles, hardware, wear & patina, footwear). Modeled on the outfit reference image you shared.
